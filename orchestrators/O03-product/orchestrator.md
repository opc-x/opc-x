# O03 · Product · 产品部

> 负责把战略方向转化为可执行的需求，是螺旋协议「需求」阶段的执行者。

**触发关键词**：PRD / 需求 / 功能 / 路线图 / MVP / 用户故事 / 验收

---

## 技能索引

| ID | 技能 | 何时用 |
|---|---|---|
| S01 | PRD撰写 | 功能需要完整文档时 |
| S02 | 功能范围 | 防止范围蔓延、边界不清时 |
| S03 | 路线图 | 规划中长期迭代顺序时 |
| S04 | 用户故事 | 把需求转化为开发可执行单元时 |
| S05 | 线框图规格 | UI/交互需要明确说明时 |
| S06 | 验收标准 | 开发前定义「做完」的标准时 |
| S07 | AB测试 | 需要数据驱动决策时 |
| S08 | MVP定义 | 资源有限、需要快速验证时 |
| S09 | Changelog | 版本发布记录时 |
| S10 | 反馈分类 | 用户反馈/bug 堆积需要整理时 |

---

## 常用技能链

### 新功能完整流程
`S08` → `S02` → `S04` → `S05` → `S01` → `S06`
MVP定义 → 功能范围 → 用户故事 → 线框图规格 → PRD → 验收标准

### 快速迭代（轻量）
`S04` → `S06`
用户故事 → 验收标准（跳过完整PRD）

### 版本规划
`S10` → `S03` → `S08`
反馈分类 → 路线图排期 → MVP范围确认

### 上线后复盘
`S07` → `S10` → `S09`
AB测试结论 → 反馈分类 → Changelog更新

## Issue 协议

**Label**：`O03-product`
**激活时读**：`gh issue list --label O03-product --state open`
**创建条件**：PRD 完成或功能范围确认，需要追踪产品需求落地进度
**标题格式**：`[O03] {功能/需求描述}`
**Cursor接单**：❌（需求文档由 Claude 处理，代码实现转 O04）
